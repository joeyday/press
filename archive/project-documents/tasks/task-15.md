# Auto-add IDs to h2 and h3 Headings

## What & Why
All `<h2>` and `<h3>` elements in rendered page HTML should have `id` attributes so that individual sections can be deep-linked via URL fragment (e.g. `/page#section-title`). If the Markdown already provides an `id` via the `markdown-it-attrs` plugin (`{#my-id}`), the existing ID is kept as-is. If no ID is present, one is generated by slugifying the element's text content using `slugify` (same options used for page permalinks: `{ lower: true, strict: true }`). Duplicate IDs within the same page are disambiguated by appending `-2`, `-3`, etc.

This is a prerequisite for the Scripture passage index, which will deep-link into the section of a page where each reference appears.

## Done looks like
- Every `<h2>` and `<h3>` in every built HTML page has an `id` attribute.
- IDs derived from text are lowercase, hyphenated slugs.
- Existing `id` attributes set in Markdown are never overwritten.
- Two headings on the same page that would produce the same slug get `-2`, `-3` suffixes.
- The feature runs as a new post-processing step that is the first to execute (before Bible ref linker and all other post-processing passes), so downstream passes and the future Scripture index can rely on the IDs being present.

## Out of scope
- `h1`, `h4`, `h5`, `h6` headings (not required).
- Updating the `allKnownUrls` set with fragment URLs (not needed).
- Any change to how other post-processing passes work.

## Tasks
1. **`addHeadingIds(html)` function** — Write a new post-processing function that parses the HTML tag-by-tag (same pattern as the other post-processors), finds opening `<h2>` and `<h3>` tags, checks for an existing `id` attribute, and injects a generated `id` if none is present. Maintain a per-page set of already-used IDs to append numeric suffixes for duplicates.

2. **Wire into the build pipeline** — Run the new function as the very first post-processing pass (before the Bible ref linker), applied to all HTML files in `dist/`.
